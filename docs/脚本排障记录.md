# 一键启动脚本排障记录

## 问题现象
用户反馈 `start.bat` / `start.sh` 没有把服务拉起来。

## 排查过程（全部真实复现）
1. 用 `timeout 90 bash start.sh` 实测：start.sh 本身能跑通（构建→启动→打印局域网地址），只是我测试时用 timeout 主动终止。
2. 用 `cmd //c start.bat` 实测 start.bat，发现三层问题：

### 问题1：UTF-8 中文破坏 cmd 批处理解析
- start.bat 内中文注释（REM 延迟打开浏览器…）以 UTF-8 保存，而 Windows cmd 按系统代码页（GBK）解析批处理
- 多字节中文字符会吞掉其后 ASCII 字节 → 整行错乱，报 `'ho' is not recognized` / `'GLM' is not recognized` 等
- **修复**：start.bat 改为纯 ASCII（英文提示），并用 Python 校验文件无 >127 的字节

### 问题2：cmd 的 timeout 被 Git Bash 的 GNU timeout 遮蔽
- bat 内 `timeout /t 4` 实际调用了 Git Bash 的 `/usr/bin/timeout` → `invalid time interval '/t'`
- 健康等待循环瞬间空转，服务未就绪就继续
- **修复**：延迟改用 `ping -n 6 127.0.0.1 >nul`（经典 cmd 延时）

### 问题3：exe 启动依赖 CWD，路径相对 CWD 失效
- 原设计 `cd /d %~dp0backend && jasperlee.exe`，在自动化环境下 cd 失效 → `jasperlee.exe is not recognized`
- 后端静态目录 `../frontend/dist` 相对 CWD 解析：从项目根启动时变成 `E:\frontend\dist` → 404
- **修复（两层）**：
  - config.go：`.env` 搜索改为「CWD + exe 所在目录」（与启动目录解耦）
  - main.go：静态目录改为相对 exe 所在目录解析
  - start.bat：直接用全路径 `"%~dp0backend\jasperlee.exe"` 启动

## 最终结果
- `start.bat` 实测：4 秒内 `http://localhost:8080` 返回 200，健康检查 OK，局域网地址正确打印
- 向量化引导改为后台异步（`go h.bootstrapIndex()`），网络慢也不阻塞启动
- GLM embedding 调用加 15s 超时 + 1 次重试；失败时聊天优雅降级（不注入知识库命中，正常回答）
